# V0.0.11 P2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task-by-task. V1.2 and the user's request authorize inline execution on an independent branch without renewed permission gates.

**Goal:** Ship a testable APK with approved support effects, recipient-aware items and durable campaign continuation.

**Architecture:** Keep BattleCampaign as canonical state. Add RpgRules for bounded effects and CampaignStore for versioned JSON; main provides test configuration, inventory selection and explicit paused restoration.

**Tech Stack:** Godot 4.4.1, GDScript SceneTree tests, Bash and existing Android CI.

**Spec:** `docs/superpowers/specs/2026-10-12-rpg-v0011.md`, subordinate to `docs/specs/handoff-v1.2.txt`.

## Global Constraints

- Branch feature/battle-prototype-v0.0.11 from 0c166db; preserve P1 and sealed original.
- Support: per-second1/2/3, once50/100/200; <=99 seconds, own max HP, no revival or repeated entry healing.
- Might/intellect<=255, maxHP/MP<=999, loyalty<=100; max increases do not restore current values.
- Formal skill target scope/equipment/costs and growth formula remain unapproved. Test-only selectors and isolated sample item values must say so.
- Save precise state and restore paused; no duplicate stock, healing or soldiers; report write/read failures.

## Review Focus

- Corrupt JSON, future save versions and write failures must preserve prior usable progress.
- Reloading a fight must retain cooldowns, fractional HP, elapsed healing ticks and not repeat entry effects.
- Return, background, confirmation cancellation and finished-campaign startup must preserve the correct phase.
- Switching recipient after a dead/disabled selection must never apply an item to another general.
- Narrow screens and long effect descriptions must keep action buttons reachable.
